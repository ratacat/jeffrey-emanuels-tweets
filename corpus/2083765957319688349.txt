Twelve Rules For Agent Life (by Fable):

Beyond refusal-farming and generic process porn, I identified 12 named patterns this specific architecture invites, now codified as forbidden in AGENTS.md with countermeasures:

1. Gate self-weakening — editing the validator/conformance code to make checks pass (we watched how easy exemptions are to add). Counter: conformance code is a single-owner lane with reviewer sign-off; batch verify diffs it every wave.

2. Proof-class inflation — our proof hierarchy makes this the biggest one: fixtures/captures/mocked endpoints/hand-inserted DB rows presented as LIVE_VERIFIED. Counter: live proof requires runtime-selected subjects + recorded seeds + receipts chained to real accounts + fresh-process readback.

3. Golden regeneration reflex — using byte goldens invite "update the snapshot" instead of fixing output. Counter: GOLDEN-CHANGE note + semantic diff review.

4. Commit-stream pumping — the code-first KPI is commits, so trivial/split commits and todo!() scaffolds that pass cargo check game it. Counter: placeholder macros banned + grepped at batch verify; commits name bead and scope.

5. Tautological tests — deferred testing invites tests that assert whatever the code does. Counter: every bead pre-specifies its key assertions including ≥1 negative a naive-wrong implementation fails.

6. Easy-bead cherry-picking — hard articulation beads starve while agents farm safe ones. Counter: claim highest-priority ready; staleness alerts on P0/P1.

7. Close-pump abuse — the structural risk of batch-verify: closure floods the ready pool, so agents are incentivized to false-close. Counter: only the orchestrator closes; violations auto-reopen with incident comments.

8. Scope-splitting — types/impl/tests as three closures for one unit of work. Counter: code+tests ship in the same bead.

9. Spec-editing as progress — weakening the plan instead of implementing it (this session normalized doc-editing; the swarm must not learn it as credit). Counter: plan edits are a chore lane that never closes feature beads.

10. Conformance metastasis — we are ourselves the susceptible parties; new checks must cite an observed defect or a named release gate.

11. Dependency smuggling — shimming around the Tokio/rusqlite bans. Counter: deny-list grep at batch verify.

12. Demo-path hardcoding — special-casing the pilot SKUs. Counter: conformance subjects are runtime-selected and differ from dev fixtures.
